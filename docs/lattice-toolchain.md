# Installing the Lattice toolchain
## On the Silverblue host:
```
toolbox create fpga
toolbox enter fpga
```

## Everything below runs inside the toolbox:
```
sudo dnf install \
yosys \
nextpnr \
icestorm \
iverilog \
gtkwave \
make
```

## openFPGALoader comes from COPR:
```
sudo dnf copr enable mobicarte/openFPGALoader
sudo dnf install openFPGALoader
```

## Verify the installation:
```
yosys -V
nextpnr-ice40 --version
icepack -h
iverilog -V
openFPGALoader --help
```

## Show installed openFPGALoader version:
```
rpm -q openFPGALoader
```







# Compiling Gatefold Verilog for the UPduino 3.1

This example takes a Verilog file generated by Gatefold, synthesizes it for the Lattice iCE40UP5K on an UPduino 3.1, performs placement and routing, creates an FPGA bitstream, and programs the board.

The complete flow is:

```text
main.v
   │
   │ Yosys
   ▼
main.json
   │
   │ nextpnr-ice40 + upduino.pcf
   ▼
main.asc
   │
   │ icepack
   ▼
main.bin
   │
   │ openFPGALoader
   ▼
UPduino 3.1
```

## 1. Verilog input

Save the Gatefold-generated Verilog as `main.v`:

```verilog
module main (
  output reg out1,
  output reg out2,
  output reg out3,
  output reg out4,
  input CLOCK_CLK,
  input reset_Y0
);
  always @(negedge CLOCK_CLK or posedge reset_Y0)
    if (reset_Y0) out1 <= 1'b0;
    else out1 <= ~(out1);

  always @(negedge out1 or posedge reset_Y0)
    if (reset_Y0) out2 <= 1'b0;
    else out2 <= ~(out2);

  always @(negedge out2 or posedge reset_Y0)
    if (reset_Y0) out3 <= 1'b0;
    else out3 <= ~(out3);

  always @(negedge out3 or posedge reset_Y0)
    if (reset_Y0) out4 <= 1'b0;
    else out4 <= ~(out4);
endmodule
```

This describes a four-bit asynchronous, or **ripple**, counter.

Each flip-flop toggles on a falling edge. The output of each stage clocks the following stage:

```text
CLOCK_CLK
    │
    ▼
  out1
    │
    ▼
  out2
    │
    ▼
  out3
    │
    ▼
  out4
```

`reset_Y0` is an asynchronous active-high reset which sets all four outputs to zero.

## 2. Create the pin constraint file

Verilog describes the logical inputs and outputs, but does not specify which physical FPGA pins they use.

Create `upduino.pcf`:

```text
set_io CLOCK_CLK 20
set_frequency CLOCK_CLK 12

set_io reset_Y0 21

set_io out1 12
set_io out2 13
set_io out3 18
set_io out4 19
```

The project directory is now:

```text
project/
├── main.v
└── upduino.pcf
```

The PCF file maps the top-level Verilog signals onto physical FPGA pins.

The onboard UPduino oscillator supplies a 12 MHz clock on pin 20 when the appropriate oscillator jumper is configured.

## 3. Synthesize with Yosys

Run:

```bash
yosys -p 'synth_ice40 -top main -json main.json' main.v
```

Yosys reads the Verilog and synthesizes it into logic suitable for the iCE40 FPGA.

Input:

```text
main.v
```

Output:

```text
main.json
```

`main.json` is a logical netlist. It describes the FPGA logic required by the design, but does not yet decide where that logic will physically reside inside the FPGA.

For additional information about what Yosys inferred, run:

```bash
yosys -p 'read_verilog main.v; synth_ice40 -top main; stat'
```

The statistics are useful for checking that Gatefold-generated Verilog is being synthesized as expected.

## 4. Place and route with nextpnr

Run:

```bash
nextpnr-ice40 \
    --up5k \
    --package sg48 \
    --json main.json \
    --pcf upduino.pcf \
    --asc main.asc
```

This tells nextpnr that the target is:

```text
FPGA:     iCE40UP5K
Package:  SG48
```

It receives both:

```text
main.json       synthesized logical circuit
upduino.pcf     physical pin assignments
```

nextpnr determines where the logic will physically reside in the FPGA and how all the resources will be interconnected.

Its output is:

```text
main.asc
```

The ASC file is the IceStorm textual representation of the placed-and-routed FPGA configuration.

The flow is now:

```text
main.v
   │
   ▼
 Yosys
   │
   ▼
main.json ─────┐
               │
upduino.pcf ───┤
               ▼
          nextpnr-ice40
               │
               ▼
           main.asc
```

## 5. Generate the FPGA bitstream

Convert the textual FPGA configuration into a binary bitstream:

```bash
icepack main.asc main.bin
```

Input:

```text
main.asc
```

Output:

```text
main.bin
```

`main.bin` is the binary FPGA configuration that can be transferred to the UPduino.

The project directory will now contain approximately:

```text
project/
├── main.v
├── upduino.pcf
├── main.json
├── main.asc
└── main.bin
```

## 6. Check that openFPGALoader recognizes the UPduino

Connect the UPduino over USB and check the available board definitions:

```bash
openFPGALoader --list-boards | grep -i upduino
```

Use the UPduino 3.1 board identifier reported by the installed version of openFPGALoader.

If it reports `upduino3`, for example, program the FPGA with:

```bash
openFPGALoader -b upduino3 main.bin
```

This transfers `main.bin` to the board.

## Complete build sequence

Once `main.v` and `upduino.pcf` exist, the entire compilation and programming process is:

```bash
# Synthesize Verilog
yosys -p 'synth_ice40 -top main -json main.json' main.v

# Place and route
nextpnr-ice40 \
    --up5k \
    --package sg48 \
    --json main.json \
    --pcf upduino.pcf \
    --asc main.asc

# Create binary FPGA bitstream
icepack main.asc main.bin

# Program the UPduino
openFPGALoader -b upduino3 main.bin
```

Thus the complete transformation is:

```text
Gatefold
   │
   │ generates
   ▼
main.v                    Verilog circuit description
   │
   │ Yosys
   ▼
main.json                 synthesized logical netlist
   │
   │ nextpnr-ice40
   │ + upduino.pcf
   ▼
main.asc                  placed-and-routed FPGA configuration
   │
   │ icepack
   ▼
main.bin                  binary FPGA bitstream
   │
   │ openFPGALoader
   ▼
UPduino 3.1
   │
   ▼
physical FPGA hardware
```

## Note about this particular counter

The UPduino oscillator runs at 12 MHz. Since this is a ripple counter, each stage divides the preceding frequency by two:

```text
CLOCK_CLK    12 MHz
out1          6 MHz
out2          3 MHz
out3          1.5 MHz
out4        750 kHz
```

These signals are much too fast to observe directly by watching LEDs.

They can be observed with an oscilloscope or logic analyzer, or the Gatefold circuit can be extended with additional D flip-flop stages until the output frequency becomes slow enough to see.

Also note that although this ripple-counter design is legitimate digital logic, FPGA designs normally use a **single common clock** for their flip-flops and implement counting using synchronous combinational logic. Ripple counters are nevertheless useful for experimenting with Gatefold-generated hardware and understanding how flip-flops compose into larger circuits.
